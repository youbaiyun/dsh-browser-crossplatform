# 安装（照着做就行）

装完你会得到：**桌面端 dsh 直接读你正在看的那个页面**，然后替你点、输入、滚动、翻页。

整个安装是**两半**：

| 要装的东西 | 从哪来 | 它是什么 |
|---|---|---|
| **扩展**（浏览器里那半） | 浏览器扩展商店 | 你在浏览器里看到的侧边栏面板 |
| **桥接插件**（桌面端里那半） | npm，一条命令 | 让 dsh 与扩展说上话，并提供 `browser_*` 工具 |

两半都装好，扩展面板会自己找到桌面端 ✓（令牌自动生成 ✓ **不需要你手填** ✓）

> **唯一有顺序要求的一条：先把扩展装进你真正在用的那个浏览器。**
> 其他都能事后补救，但扩展如果不在那个浏览器里，**任何东西都装不进去**——包括桌面端。
> 桌面端能替你启动浏览器，也能在"缺的就是扩展"时告诉你**并直接打开**正确的扩展页，
> 但它没法替你安装：浏览器只加载被明确安装过的扩展。从 Chrome 137 起，
> 带品牌的 Chrome/Edge 已直接忽略 `--load-extension` 命令行参数；即便在仍认这个参数的浏览器里
> （Chromium、Chrome for Testing），那种加载也只活一个会话、什么都不安装。
> 注意扩展是**按浏览器配置隔离**的：装在 Edge 或另一个 Chrome 配置里，对你的默认浏览器没有任何帮助。

**适配范围**：**Windows / macOS / Linux 都支持** ✓（其中 Linux 由 CI 每次都跑完整链验证）；dsh 桌面端（Node ≥ 20）+ 桌面 Chrome / Chromium / Edge **116+** 或 Firefox **140+**；**手机与平板不支持**（没有侧边栏这种界面，且桥接的免令牌通道与特权方法只在回环上）。

完整的最低版本与依据见仓库 README 的「适配范围」。
**手机和平板不支持**：那边没有侧边栏界面，扩展商店也不支持装第三方扩展；而且桥接的免令牌通道与特权方法都留在回环上，手机本来也连不到你电脑上的 127.0.0.1。

## 第 1 步：装扩展

打开你浏览器的扩展商店页面，点「添加至 Chrome / 添加到 Firefox」，确认。

> ⚠️ 商店版本**尚未发布**时（审核中），商店里搜不到。这时只有开发者能装：
> 在 `chrome://extensions` 打开「开发者模式」→「加载已解压的扩展程序」→ 选**那个含
> `manifest.json` 的文件夹**（仓库里是 `extension/dist`；从 Release 下载的话，先把
> `dsh-browser-crossplatform-<版本>.zip` 解压，选解压出来的那个目录）。
>
> **务必用不带 `-store` 的那个 zip。** 带 `-store` 的是给商店上传用的，它的 manifest
> **没有 `key`**，手动加载后扩展 id 不在桥接的白名单里——连接会被拒，你会看到侧边栏一直
> 未连接。不带 `-store` 的版本带 `key`，id 固定且已在白名单内，装完直接能连。
>
> 普通用户请等商店上架后再装。

**必须装进你真正在用的那个浏览器**：扩展是按浏览器/配置隔离的。如果你的默认浏览器是 Chrome，
而扩展只装在 Edge 里，那两边都连不上——桌面端也会如实告诉你这一点。

## 第 2 步：装桥接插件（一条命令）

在能运行 dsh 的终端里：

```sh
dsh plugin --profile desktop add dsh-browser-crossplatform
```

**profile 名要和你实际用的一致**：dsh **桌面端**用 `desktop`；命令行版 `dsh web` 用 `web`。
（不确定就看你机器上的 `~/.dsh/profiles/` 目录里叫什么。）

装完**重启一次 dsh**。重启后插件设置页会出现，标题是「**dsh 浏览器扩展（全平台）的桌面端一半**」。

## 第 3 步：确认装好了（30 秒）

```
① 打开任意一个网页
② 点开 dsh 的浏览器侧边栏面板
③ 面板顶部应当显示**已连接**（不是"未连接"）
④ 让模型读一次这个页面：它会说出页面标题与上面的按钮/链接
```

四条都对 → **装好了** ✓

## 第 4 步（可选）：让模型能看图

看图**默认关闭** ✓（开启后每看一张图约多花一秒，图会离开这台机器发给你配置的模型）。

要开的话，先让桌面端能拿到密钥，二选一：

```
· 在桌面端的凭据里提供 DEEPSEEK_API_KEY（推荐，密钥不落文件）
· 或在此插件的设置页里填「看图 API key」（visionApiKey）
```

然后在面板的「看图」里选一档：低档说图里有什么；标准档再和页面文字对一下；增强档再问它在页里干什么。
不用了随时调回关闭 ✓

## 装不上时按这个顺序看

| 现象 | 多半是 |
|---|---|
| 面板一直显示"未连接" | 第 2 步没做，或做完**没重启** dsh |
| 插件设置页里找不到「dsh 浏览器扩展（全平台）的桌面端一半」 | `--profile` 的名字不是你桌面端用的那个 |
| 面板能连、但模型说页面是空的 | 页面试试刷新一次再读（受限页面如 `chrome://` 读不到，属正常） |
| 开了看图却提示不可用 | 第 4 步的密钥还没配好 |

## 卸载

```
dsh plugin --profile desktop remove dsh-browser-crossplatform     # 桌面端那半
浏览器扩展页 → 移除                                              # 浏览器那半
```

## 常见问题

### 如何安装 dsh 浏览器扩展？

两半都要装：扩展从浏览器扩展商店装；桌面端那一半用一条命令
`dsh plugin --profile desktop add dsh-browser-crossplatform`，然后重启 dsh。详见上面第 1、2 步。

### 装完怎么确认能用？

打开任意网页，点开 dsh 的浏览器侧边栏面板：顶部显示**已连接**，让模型读一次页面能说出标题与按钮，
就算装好了。四条自检见上面第 3 步。

### dsh 浏览器扩展支持哪些平台？

Windows / macOS / Linux 上的 dsh 桌面端，配桌面 Chrome / Chromium / Edge 116+ 或 Firefox 140+。
手机与平板不支持（没有侧边栏界面，且桥接的免令牌通道与特权方法只在回环上）。

### 为什么面板一直显示"未连接"？

按这个顺序查：

1. **你正在用的那个浏览器里没装扩展。** 这是最常见的一种，而且桌面端替不了你——见本页开头那段。
   打开浏览器的扩展页（`chrome://extensions`、`edge://extensions`）看一眼：列表里没有它，别的都白搭。
   扩展是按浏览器配置隔离的，装在别的浏览器或另一个 Chrome 配置里不算。
2. **桌面端那一半还没装**（第 2 步），或者装完**没有重启** dsh。
3. **装了但被停用了**，或因为是以未打包方式加载被 Chrome 禁用。在扩展页把它启用即可。
4. **扩展的 id 不在桥接的白名单里**，于是免令牌的回环连接被拒，套接字以 `4002`（`bad token`）关闭。
   这看起来就像版本不匹配：桥接配置里的 `extensionId` 默认只列本项目已知的那几个 id，而来自别处
   的构建 id 不同。**从面板上看不出这一条**——状态一直停在"未连接"——所以要么从商店装扩展，
   要么把那个构建的 id 加进 `extensionId`（在 `chrome://extensions` 能看到，多个用逗号分隔）。

### 浏览器本来是关着的，模型说打不开

第一次这样是正常的：浏览器只有在扩展已安装的情况下才会加载它。
你自己先把浏览器打开、装一次扩展（第 1 步），之后桌面端就能替你启动浏览器了——
它打开的是**你本来就在用的浏览器**、不加任何额外参数，而且当那个浏览器已经在运行**且开着窗口**时**不会**再开一个窗口（若它只剩进程、没有窗口，则会启动一次把窗口要回来）。
如果发现扩展哪个配置里都没装，它会明确说出来，并直接替你打开正确的扩展页。

### 需要自己去哪里找令牌吗？

**Chrome / Edge：不需要。** 桥接在首次启动时自动生成令牌并保存在 `~/.dsh/ext-bridge-token`（权限 0600），
而扩展根本不需要看到它：来自**本扩展**的回环连接（按 id 匹配，即插件配置里的 `extensionId`）可以免令牌。
所以零配置发现才能成立。

**Firefox：需要手填一次。** Firefox 始终要出示令牌——它的 `moz-extension://` 来源带的是每次安装都不同的
UUID，而不是稳定的插件身份，桥接无法确认那确实是本扩展，于是要求凭据。扩展自己没有办法读取那个文件，而
面板里**也没有**填它的输入框——地址与令牌是被有意从设置表里去掉的，因为在受支持的那条路径上它们不该由用户决定。
所以 Firefox 上要在侧边栏的 DevTools 控制台里把令牌写进扩展自己的存储一次：

```js
chrome.storage.local.get('dshSettings').then(({ dshSettings }) =>
  chrome.storage.local.set({ dshSettings: { ...dshSettings, token: '<~/.dsh/ext-bridge-token 的内容>' } }))
```

然后**重载扩展**：设置只在启动时读取一次，代码里没有 `storage.onChanged` 监听，所以控制台写入要等重载才生效。
之后它就会被记住。
